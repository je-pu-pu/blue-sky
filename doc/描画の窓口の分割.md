# 描画の窓口の分割（設計上の問題 D3）

2026-11-11 に書いた。数は同じ日の `feature/ui-library` の HEAD（355c138c）で数えた。

## 1. 何が困っていたか

`blue_sky::graphics::GraphicsManager`（`source/blue_sky/graphics/GraphicsManager.h`）は、core の `core::graphics::GraphicsManager`（`source/core/graphics/GraphicsManager.h`）を継承し、Direct3D 11 の実装 `blue_sky::graphics::direct_3d_11::GraphicsManager` が 1 つだけある。

- 仮想関数（ヘッダの宣言の行。オーバーロードは別に数える） : blue_sky 65（うち純粋 51）・core 33（うち純粋 29）
- 偽物を作るには、blue_sky の純粋 51 と、core の純粋のうち blue_sky が埋めていない 17 の、約 68 個を埋める必要がある。しかも blue_sky の GraphicsManager はコンストラクタで紙のテクスチャ・フェーダーなどを持つので、継承した偽物は重い
- 使う側（ECS のシステム・ステージ・UI）は GraphicsManager の全体を受け取るので、何を使うかが型から見えない

そのため、描画の周りのテストは「GraphicsManager に nullptr を渡し、描画の所を通らない」ものしか無かった（`ObjectRenderDataSystemTest`・`ObjectFactoryTest` など）。

数え方 : `source` の下の .cpp・.h（lib・extern を除く）で、受け手が `get_graphics_manager()->`・`graphics_manager_->`・`graphics_manager->`・`gm_->`・`gm->`・`context.graphics_manager->` の呼び出し。GraphicsManager 自身の .h・.cpp の中は数えない（「外から未使用」に入る）。

## 3. 分け方

使う側の実際の使い方に合わせ、純粋仮想だけの小さな窓口（インターフェース）を作る。GraphicsManager はそれらを全部実装したまま（多重継承）にし、使う側は小さな窓口だけを受け取る。窓口どうしは継承で重ならないので、仮想継承は要らない。

| 窓口 | 置き場所 | 関数 | 使う側 | 理由 |
|------|---------|------|--------|------|
| `ResourceResolver`（ハンドル・名前から引くだけ。const） | `blue_sky/graphics/ResourceResolver.h` | resolve_model・resolve_texture・get_model_handle・get_texture_handle | ObjectRenderDataSystem・PlayerBehaviorSystem | 毎フレーム動く System は引くだけで、読み込み・作成をしない。const の窓口にすると「描く前に資源を作らない」ことが型で分かる |
| `ResourceLoader`（読み込みと作成。ResourceResolver を継承） | `blue_sky/graphics/ResourceLoader.h` | load_model・clone_model_with_shaders・get_texture・create_constant_buffer | ObjectFactory・GameObjectRef・RobotBehaviorSystem | 物体を作るときだけ資源を読む・作る。偽物は 8 個埋めれば作れる |
| `RenderSettings`（描画の設定） | `blue_sky/graphics/RenderSettings.h` | set_sky_box・unset_sky_box・set_ground・set_ambient_color・set_shadow_color・set_shadow_paper_color・set_drawing_accent・set_drawing_line_type・set_paper_texture_type | ステージの見た目（新しく作る `stage::StageLook`。run_action の set・fade と毎フレームの値）・StageBuilder | ステージのデータ（TOML）が変えるのはこれだけ。偽物で「ステージの set・fade が描画の設定を正しく呼ぶ」を確かめられる。Scene の線の揺れ（update_constant_buffer_for_sprite_frame）は同じ関数の中で定数バッファ（低レベル）も書くので、GraphicsManager の全体のまま |
| `Canvas2D`（2D の画像と文字を描く。UI の画像を読む） | `blue_sky/graphics/Canvas2D.h` | get_screen_width・get_screen_height・get_render_target_width・get_render_target_height・get_sprite・queue_text・flush_text・measure_text_width・measure_text_line_height・get_default_font_size・load_named_texture_premultiplied | ui::Renderer | UI の描画が使うのはこれだけ。偽物（と偽の Sprite）で、仮想座標から画面への写し方・文字と Sprite の切り替え・画像の読み込みを確かめられる。UI の画像の読み込みは ui::Renderer だけが使うので ResourceLoader ではなくここに置く（1 つの窓口で UI が描ける） |

`run_action` の描画の部分は GamePlayScene のメンバ（色を追う値 `ambient_color_` など）と混ざっていて、シーンごと作らないと試せなかった。描画の設定に関わる状態（光の位置・環境色・影の色・紙の影の色・線の揺れの大きさ・陰影の有無）と、set・fade の当て方・毎フレームの追い方・描画の設定への当て方を `blue_sky::stage::StageLook`（`blue_sky/stage/StageLook.h`）に移し、GamePlayScene はそれを持って呼ぶだけにする。

### 窓口に分けないもの（理由）

- **フレームの流れ・描画先・フェード・デバッグ表示・画面とビューポート** : 使うのはシーン（15）と GameMain と core の RenderSystem だけ。シーンは `Scene( GameMain& )` で GraphicsManager の全体を近道で受け取り（CLAUDE.md の「サービスの探し方」）、GameMain は持ち主・組み立ての根。窓口を作っても受け取る側が変わらず、使われない窓口が増えるだけなので作らない。シーンを分けてテストしたくなったら、そのときに使う側に合わせて作る
- **低レベル（入力レイアウト・テクニック・定数バッファ）** : 使うのはシェーダーの中身で、Direct3D 11 のデバイスなしでは動かない。偽物で試す意味がないので分けない
- **core の GraphicsManager** : core 層から使うのは RenderSystem・ParticleRenderSystem（フレームの流れと低レベル）・NeuralNprEffect（ポストエフェクト）・描画の部品（count_draw）。いずれも Direct3D 11 の描画そのもので、上と同じ理由で分けない。core の `resolve_model`・`create_constant_buffer` は ResourceResolver・ResourceLoader と同じ形にし、GraphicsManager の 1 つの関数が両方を満たす

## 4. 消す関数

どこからも呼ばれていないもの（テスト・Lua を含めて確かめた）: `load_model_handle`・`replace_model`・`get_model_handle( 名前 )`・`get_mesh_handle`・`resolve_mesh`（と使われていない型 `MeshHandle`）・`load_named_texture_handle`・`get_light_direction`・`reset_light_direction`。

中だけで使うものは公開をやめる（protected へ）: `create_mesh_buffer`・`unload_named_texture`（仮想もやめる。上書きする所が無い）・`clear_pass_count`・`count_pass`・`clear_draw_count`。`get_back_buffer_texture` も中だけだが、core の純粋仮想なので触らない。

残すもの : `load_named_texture_premultiplied_async`・`get_async_load_count`（と `start_texture_load_async`）は外から使われていないが、B23 の「非同期の読み込みの仕組み。シーンの読み込みを非同期にする後続の作業で使う」として残すと決めてあるので消さない。

## 5. 段階

各段階でゲームが動き、テストが通るようにする。画面・ログは変えない（移す前の exe と画素の差・ログを比べる）。

1. 使われていない関数を消し、中だけで使う関数を protected にする
2. `RenderSettings` を作り、`stage::StageLook` に run_action の描画の部分を移す。StageBuilder も RenderSettings で受け取る。テスト : StageLook（set・fade・毎フレームの当て方）・StageBuilder（地面）
3. `ResourceResolver`・`ResourceLoader` を作り、ECS のシステム・ObjectFactory・GameObjectRef を書き換える。テスト : ObjectRenderDataSystem（見えない物・隠した物・モデルの無い物の定数を書かない、線の色を書く）・ObjectFactory（種類名でモデルを読み、定数バッファを作る）・RobotBehaviorSystem（見た目のテクスチャを名前で読み、ハンドルで持つ）
4. `Canvas2D` を作り、ui::Renderer を書き換える。テスト : ui::Renderer（仮想座標から画面への写し方・文字と Sprite の切り替えで文字を先に描く・画像の読み込みの失敗を覚える・文字の幅をスケールで戻す）

## 7. ゲームから Direct3D 11 を見えなくする（2026-11-12）

利用者の方針 :「ゲームは Direct3D を意識するべきではない」。窓口を分けた後も、ゲームの側（Scene・blue_sky）と core の抽象に Direct3D 11 の型・ヘッダが残っていた（描画の窓口の `get_direct_3d`・ゲームの定数バッファの型・物理のデバッグ表示・フレームの保存の読み戻し・VR のヘッダ・Shader の imgui の dynamic_cast）。

### 決まり

Direct3D 11 の型・ヘッダ（`core/graphics/Direct3D11/*`・`blue_sky/graphics/Direct3D11/*`・`d3d11.h`・dxgi・`ID3D11*`・`DXGI_*`・`D3D11_*`・`direct_3d_11::`）を知ってよいのは次だけ。

| 場所 | 理由 |
|------|------|
| `blue_sky/GameMain.*` | 組み立ての根（Direct3D を作り、実装を作って抽象の窓口として渡す。ヘッダは前方宣言だけ） |
| `core/graphics/Direct3D11/`・`blue_sky/graphics/Direct3D11/` | 描画の実装 |
| `test/graphics/EffectParserTest.cpp`・`MsdfFontTest.cpp` | 実装を直接試すテスト |

App・Main.cpp も組み立ての根だが、今は Direct3D を知らない。決まりは `test/graphics/Direct3DBoundaryTest` が確かめる（source の .h・.cpp を読み、コメントと文字列を除いた中を調べる。例外の表が古くなったら、それも失敗にする）。

### 直し方（足した・変えた窓口と理由）

| 破っていた所 | 直し方 | 窓口をどこに置いたか・理由 |
|------------|--------|------------------------|
| ゲームの定数バッファの型（`blue_sky/ConstantBuffers.h`・`core/ConstantBuffers.h`・`type.h`）が Direct3D 11 のテンプレート | `core::graphics::ConstantBufferTyped< Data, Slot >`・`ConstantBufferWithData`（抽象の `ConstantBuffer` の派生で、実装のバッファを持って取り次ぐ）。実装は `direct_3d_11::create_typed_constant_buffer< T >` で作る | 型（中身・場所）だけをゲームが決め、GPU のバッファは実装が持つ。Direct3D 11 のテンプレートの定数バッファは消し、実装の中（Sprite・ShadowMap・MSDF）も同じ型にした（同じ物が 2 つにならないように） |
