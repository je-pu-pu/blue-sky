# blue-sky システム階層スタック（依存は下向きのみ）

[動詞とゲームシステム.md](動詞とゲームシステム.md) の各システムを、**厳密な階層構造（スタック）**に整理したもの。
手法は bytesbeneath「System Stack Method」に準拠。

## 原則

> **各システムは、自分より下位（前段）の層のデータにのみ依存してよい。自分に依存する後段の層へ手を伸ばしてはならない。**

- 依存の矢印は**常に下向き**（前段のみ）。循環・上向き依存を作らない。
- スタックはそのまま **1フレームの実行順** でもある: **Input → Update（シミュ層を下から上へ）→ Render**。下位ほど先に走り、上位ほど後に走る（コンピュータの逐次実行＝組み立てライン）。
- OOP の「現実をオブジェクトで写像」ではなく、**データフロー**で考える（前段が生んだデータを次段が読む）。
- 層をまたぐフィードバック（行動→敵が反応、遭遇→敵増加）は、**上位が下位の状態(Save/Load・状態ストア)を更新**する形で表す。下位は「誰が更新したか」を知らない＝上向き依存にならない。
- **プレイヤーと敵AIは互いを直接参照しない**。両者は「世界状態（要素・知覚）」という下位層を介してのみ相互作用する（= systemic AI／創発の本質、かつ層を疎結合にする鍵）。

---

## システム抽出（3パス）

動詞（飛ぶ/隠れる/逃げる/隙を突く/探索する）から、**action / simulation / presentation** の3観点で必要システムを洗い出す。

| パス | 問い | 出てくるシステム |
|---|---|---|
| **Action（動詞→操作）** | プレイヤーは何をする？ | 飛行・ステルス（隠れる/逃げる/隙を突く）・道具使用・探索移動 |
| **Simulation（世界のルール）** | それが成り立つには世界がどう振る舞う？ | 物理・要素相互作用(水/電気/火/煙)・知覚(視界錐/聴覚)・ナビ(navmesh)・敵AI(状態機械)・失敗/敵増加・資源経済・進行 |
| **Presentation（提示）** | それを見せる/伝えるには？ | 描画・カメラ・アニメ・パーティクル(煙/火)・UI(資源/警戒/高度の HUD)・視界錐の可視化 |

## 全体図（下＝基盤で先に走る、上＝提示で後に走る）

```
                         ── Render パス（最後・全状態を読むだけ）──
┌──────────────────────────────────────────────────────────┐
│ P  プレゼンテーション   Render / Camera / Animation / Particles / UI / 視界錐可視化 │  ← 誰からも依存されない
└──────────────────────────────────────────────────────────┘
                         ── Update パス（シミュ層を下から上へ）──
┌──────────────────────────────────────────────────────────┐
│ S7 進行・パワーカーブ    W0/W1/W2 の動詞重み / 解禁順 / per-stage 無双               │
│ S6 失敗・帰結（永続）    死亡→ステージ先頭 / 敵増加(上限) / 警戒持続 / 強化リセット      │
│ S5 遭遇・解法            1遭遇=複数解法 / 無力化・死体隠し / ドロップ・拾い（→基盤状態へ）  │
│ S4 プレイヤー動詞        飛ぶ / 隠れる・逃げる・隙を突く / 道具使用                     │
│ S3 敵システミック AI     警戒状態機械(無警戒→不審→捜索→警報) / 刺激反応 / 追跡           │
│ S2 知覚・ナビゲーション  視界錐・聴覚 / navmesh＋オフメッシュリンク                    │
│ S1 系統ルール（要素）    水・電気・火・煙・寒さ … と相互作用ルール                     │
└──────────────────────────────────────────────────────────┘
                         ── Input パス／基盤（毎フレーム最初）──
┌──────────────────────────────────────────────────────────┐
│ F  基盤              Entities(ECS) / Input / Time / Assets / Save-Load＋状態ストア │
│                     / World・Spatial(街・縦軸・LOS/距離/高度) / Physics           │  ← 何にも依存しない
└──────────────────────────────────────────────────────────┘
        （F の下に既存エンジン層 core / 各 Manager が続く）
```

依存は各行から**下の行へのみ**。隣接に限らず、より下の任意の層を使ってよい（例: S4 は F の縦移動物理を直接使う）。

> **設計意図（物語・テーマ）はスタックの層ではない**。ランタイムのシステムではなく、全層が「体現する」意図（心理アーク／「力で得たものは残らない」等）。メカニクスはテーマを参照しない＝テーマを変えても下位は壊れない。→ 末尾「設計意図」参照。

## 各層の詳細（依存＝下向きのみ）

### F 基盤（依存なし。Input パス＋永続状態。毎フレーム最初）
- **Entities(ECS)**: 実体とコンポーネント。
- **Input**: 入力。 **Time**: 時間。 **Assets**: アセット。
- **Save/Load ＋ 状態ストア**: 強化資源・消費アイテム所持・警戒レベル・敵増加数・per-stage 強さなど**永続/セッション状態**（純データ、ロジック無し）。上位がここを読み書きする。
- **World・Spatial**: 街の自動生成ジオメトリ、**縦軸＝高さ**、空間クエリ（視線 LOS・距離・高度）。
- **Physics**: 物理（衝突は Entities とハード結合しうる＝必要な結合は許容）。

### S1 系統ルール（要素）
- 水・電気・火・煙・寒さ等と**相互作用ルール**（水＋電気＝感電で範囲停止 等）。
- **依存**: F（物理・世界・状態）。個々にルールを与えるだけ、組合せの解はプレイヤーが発見。

### S2 知覚・ナビゲーション（中立サービス）
- 視界錐（可視化）・聴覚の**知覚**、navmesh(Recast & Detour)＋オフメッシュリンクの**経路探索**。
- **依存**: F（ジオメトリ・LOS）、S1（煙が視界を遮る等）。
- **要点**: プレイヤー/敵の**どちらの型も知らない**中立サービス（循環回避の要）。

### S3 敵システミック AI
- 警戒の状態機械（無警戒→不審→捜索→警報）、刺激反応（音/停止ロボ発見/視界喪失）、追跡。対空タイプの例外知覚。
- **依存**: S2（知覚・ナビ）、S1（要素刺激）、F（警戒状態の保持）。
- **要点**: **プレイヤー(S4)を直接参照しない**。世界に現れた刺激を知覚で拾ってルール反応するだけ。

### S4 プレイヤー動詞（能力）
- 飛ぶ（消費・上がる/降りる）、隠れる/逃げる/隙を突く、道具使用（風船・傘・花火・煙玉・フリーズ）。
- **依存**: S3（AI の視線・状態を**読んで**回避/利用）、S2（知覚を欺く）、S1（要素を発火）、F（資源を消費・縦移動物理）。
- **要点**: 能力の効果は「世界(S1/S2)に刺激を置く」形で出す → 敵(S3)は知覚で拾う＝世界越しの相互作用（上向き依存なし）。

### S5 遭遇・解法
- 1遭遇=複数解法（ghost/掃討/飛び越え/環境利用）、無力化（背後・上・電源カット・センサー破壊）、死体隠し。
- **依存**: S4・S3・S1。
- **書込（下向き）**: 撃破ドロップ／拾いで **F の状態ストアに資源を加算**。上位→下位の書込は可（依存は下向き）。

### S6 失敗・帰結（永続）
- 死亡/捕捉→ステージ先頭（オートセーブ再開なし）、**敵増加(上限・基本戻らない)**、警戒持続、強化リセット、正面被弾(HP)。
- **依存**: S5（遭遇結果）、F（状態＝敵数/警戒を更新、世界へ敵再配置）。
- **則**: 敵増加上限は「強さゼロからでもクリア可能」な範囲（死のスパイラル回避）。

### S7 進行・パワーカーブ
- ワールド別の動詞重み（W0 飛行主武器／W1 隙を突く=破壊・無双多め／W2 飛行手放し）、解禁順、per-stage 無双。
- **依存**: S4（動詞の権能調整）、S6（失敗/リセットの重み）、S5。
- **要点**: 解禁順＝心理アーク。強さは per-stage で消える。

### P プレゼンテーション（Render パス。最後・全状態を読むだけ）
- **Render**（視界錐の可視化含む）／**Camera**／**Animation**／**Particles**（煙・火の描画）／**UI**（資源・警戒・高度の HUD）。
- **依存**: F〜S7 の**状態を読むだけ**（書き戻さない）。誰からも依存されない最上段。
- **要点**: シミュ結果を提示に変換するだけ。ゲームロジックを持たない。ここにロジックが漏れると層が壊れる。

## 「下向きだけ」を成立させる3つの仕組み

1. **永続状態(F: Save/Load・状態ストア)で入出力を分離**: 資源は「入手(S5)」と「消費(S4)」が別層。両者は F の状態を介すだけで互いを知らない。
2. **世界越しの相互作用(S1/S2)**: プレイヤー(S4)と敵AI(S3)は直接参照せず、要素・知覚という下位の世界状態を通じてやり取りする（systemic AI の本質）。
3. **上位が下位に書き込む一方向**: フィードバック（遭遇→敵増加、行動→警戒上昇）は上位が下位状態を更新する形。下位は「誰が更新したか」を知らない。

効果: ある層を差し替え・テストする時、**下位だけ用意すれば動く**（上位はモック不要）。P（提示）や S7（進行）、テーマを大きく変えても、F〜S5 のメカニクスは無傷。

## 実装への示唆（依存方向 = include 許可リスト）

- **上位 System は下位のインターフェース/コンポーネントのみ include する**。逆向き include（例: 知覚 System が プレイヤー能力 System を include）を**禁止**＝この階層図が include グラフの許可リスト。
- ECS 対応: F は Entities/Input/Time/Assets/物理/状態サービス。S1–S3 は Perception/Nav/AI などの System＋Component。S4 は プレイヤー入力→能力 System。P は描画/カメラ/UI System（読み取り専用）。
- **S2/S3（知覚・AI）を「プレイヤー/敵の型を知らない中立サービス」に保つ**のが循環依存回避の最重要ポイント。
- F の下に既存エンジン層（`core` / ECS / 各 Manager）が続く。エンジンはゲーム層を知らない（既存のレイヤー階層と一致）。

## 設計意図（物語・テーマ）＝ スタックの外
心理アーク（憧れ→挫折→もがき→気づき→肯定）、エンディング（自発的に飛ぶのをやめ地に立つ）、「力で掴んだ花は枯れる／奪ったものは残らない」を**メカニクスで体現**する。これは**ランタイム層ではなく設計意図**であり、S7 の per-stage 無双や S4 の飛行資源制などが「体現」する。メカニクスは意図を参照しない＝意図を変えても下位は無傷。
