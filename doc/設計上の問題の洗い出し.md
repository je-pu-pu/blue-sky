## 0. この文書について

UI の画像対応までを終えた段階で、設計上の問題を広く洗い出した。範囲を 3 つに分け、それぞれ別のサブエージェントにコードを読ませて調べた。

1. UI ライブラリ本体（`core/ui`・`core/setting`）
2. UI が乗っている描画基盤（`core/graphics`・`blue_sky/graphics`・MSDF の文字描画・リソース管理・シェーダー）
3. アプリへの組み込み（GameMain・App・シーン・入力・設定ファイル・サービスの参照）

既知の課題は除いた（`doc/UIライブラリ設計.md` 2.2 の見送り項目と、`doc/UI画像対応と既存コードの修正.md` 6 章の後続課題）。

### 確かめ方と、その限界

- 指摘は全部で 60 件ある。重なるものは 1 つにまとめた。
- 次の 10 件は、まとめる段階でコードを開いて確かめた（**確認済み**と書いたもの）。
  - SettingStore の `get<T>` が型の違いで黙って既定値を返す
  - 決定・キャンセル・方向の入力が親の部品へ回らない
  - technique の表のキーがポインタになっている
  - 文字のアトラスが空いたセルを使い回さない
  - 定数バッファのコピーコンストラクタ
  - シェーダーのホットリロードの TODO
  - オプション画面が確認ダイアログの前に保存している
  - 設定ファイルの空の値の行で例外が出る
  - 遷移に失敗すると毎フレーム保存する
  - `is_transparent` の扱い（直前の作業で確認）
- それ以外は、サブエージェントがコードを読んで報告した内容で、私は裏を取っていない。報告で「推測」とされたものは「（推測）」と書いた。
- 場所の行番号は、報告の時点のものでずれていることがある。ファイル名と関数名で探すこと。

### 重要度の分け方

- **A：今すぐ直すべき不具合**。データを失う、起動できない、落ちる、表示が消える、など。
- **B：次の機能を足す前に直すべき構造の問題**。このまま機能を足すと手戻りが大きくなる。
- **C：品質を上げる改善**。

| B4 | **文字列キーと表示する文字列が同じ型**で、未登録のキーはキーそのものを返す。未登録のときは引数への参照を返す | 翻訳漏れを機械的に検出できない。表示する文字列（プレイヤー名など）が既存のキーと同じだと置き換わる。`const auto& s = tr( ... )` と受けると、未登録のときだけ壊れた参照になる | キーを専用の型（`TextKey`）にする。未登録のときは値で返してログに出す。翻訳が欠けたときの代わりの言語を持たせる |
| B5 | **変化の通知がない**（フォーカス・値・文字列の変化）。毎フレーム getter で読み直す前提 | フォーカス枠の移動や値の変化の演出、読み上げ、言語の切り替え時の再レイアウトが書けない | `on_focus_changed`・`on_value_changed`・`invalidate_measure()` を設ける |
| B6 | **SettingStore が型安全でない**。型の違いも未登録のキーも、黙って既定値を返すか無視する（**確認済み**）。範囲（最小・最大・刻み）をストアと UI の 2 か所に書いている | 型やキーの書き間違いに気づけない。設定を 1 つ足すのに 4〜5 か所を触る | 型付きのハンドル（`Setting<float>`）にする。範囲・ラベル・説明をストアのメタデータに持たせ、そこから部品を作る |
| B7 | **層は「入力を奪う全画面のモーダル」だけ**。画面遷移は文字列で、引数を渡せない | 入力を奪わない HUD・トースト・ツールチップ、部品から開くドロップダウン、「操作タブを開いた状態でオプションを開く」が作れない | 層に属性（モーダルか、入力を下へ通すか、位置の基準）を持たせる。遷移は型付きの引数で行う |
| B8 | **フォーカスの移動が 1 方向の Stack 専用** | インベントリ・セーブスロットのタイル・ソフトキーボードのような 2 次元の配置で、矢印で移動できない | Grid コンテナを足す。矩形の位置関係で一番近い部品へ移る方式も選べるようにする |
| B9 | **ラベル付きの行を継承で作っている**。タブの見出しは部品ではなく矩形の配列 | ラベルのないスライダー、アイコン付きの行、印の付いたタブが、新しいクラスを書かないと作れない | 値を操作する部品だけを独立させ、行は Label と組み合わせて作る。タブの見出しも部品にする |
| B10 | **Screen が具体的な部品の Dialog に依存している**（`dynamic_cast`・friend で部品の中身を直接書き換える） | 新しいモーダル部品（入力欄付きの確認、ポップアップメニュー）を足すたびに Screen を直す | 最初のフォーカス先は `Widget::get_initial_focus()` で決める。`show_dialog` は Screen の外へ出す |
| B11 | **ポインタやキーの捕捉が外れたことを部品に知らせない**。クリック判定を 5 つの部品が書き写している | 層を積んだときに、ボタンが押された見た目のまま残る。キー待ちが背面に残る（推測） | `on_capture_lost()` を設け、クリック判定を共通の部品にまとめる |
| B12 | **寸法・比率の直書きが多く**、行の高さと文字サイズが連動しない | 文字サイズを 1.5 倍にすると、文字が行からはみ出す。テーマファイルでも変えられない | 寸法をテーマに移し、行の高さを「文字の行の高さ＋余白」から決める。`ui_scale` と `text_scale` を設定に持たせる |
| B13 | **仮想画面が 1920x1080 で固定**。位置の基準（アンカー）もセーフエリアもない | 21:9 の画面で HUD を端に寄せられない。テレビ向けの余白が取れない | 短い辺だけを固定し、長い辺は画面に合わせて伸ばす。画面の端を基準にした位置指定とセーフエリアを持たせる |
| B14 | **オプション画面のロジックが GameMain などのシングルトンに直結**していて、テストがない | A1 のような不具合が、テストで見つからない構造になっている | 適用・確認・ロールバック・保存の流れを `OptionsController` に分け、依存は外から渡す |

### 2.2 描画基盤（7 件）

| # | 問題 | 何を足そうとすると破綻するか | 直し方の方向 |
|---|------|---------------------------|-------------|
| B15 | **Sprite と文字の描画が別々の仕組み**で、描画の順番を保証するものがない（今は両方とも即時に描くので正しく見えているだけ） | 6 章のバッチ化を別々に入れると、「パネル → 文字 → その上のパネル」の順番が崩れる | 2D の描画命令を 1 本の命令リストに積み、状態が変わるところでだけまとめて描く仕組みにしてから、バッチ化する |
| B16 | **2D の座標変換が Sprite と文字の 2 か所に重複**している。どちらも描画先ではなく、スワップチェーンの大きさで決め打ちしている | 画面と違う大きさの描画先（VR の目ごとのバッファなど）に UI を描くと、位置がずれる。立体視のずらしが文字だけ効かない | ピクセル座標をクリップ空間に写す 1 つの行列にまとめ、描画先の大きさから作る |

| B18 | **描画状態を Effects11 の Apply に任せている**。「Apply の後にリソースを全部設定し直す」という暗黙の決まりがあり、フレームの頭で状態を初期化しない | 新しい描画を足す人が決まりを知らないと、何も描かれない。前のフレームの状態に依存した崩れが出る（UI の上の縦線の原因の候補。推測） | 描画状態を C++ 側で明示的に指定する方式にする。少なくとも、フレームの頭とオーバーレイの前で初期化する |
| B19 | **抽象層に D3D11 と Effects11 の型が漏れている**。2D と文字の描画は抽象層になく、ゲーム側にしかない | 別の API（D3D12・Vulkan）へ移るときや Effects11 から抜けるとき、抽象層ごと作り直しになる。core 層から文字が描けない | 形式などはエンジン独自の型にする。2D と文字の描画のインターフェースを core に上げる |
| B20 | **リソースの所有が生ポインタと名前だけ**。同じ名前で登録し直すと古いものが残る。画面サイズに依存するリソースを作り直すと、持っている側のポインタが無効になる | 6 章の「UI テクスチャの寿命」と同じ種類の無効なポインタが、UI 以外でもすでに生まれ得る | 世代番号付きのハンドルにする |
| B21 | **色空間の方針がない**（ガンマ空間でのブレンド。3D 用の読み込みは、PNG によって sRGB と UNORM が混ざる） | 素材によって明るさが変わる。半透明を重ねると濁る。後から線形にすると、全素材の見た目が変わる | テクスチャごとに色空間を明示し、描画先を sRGB にする方針を決める |

## 3. C：品質を上げる改善

### 3.1 UI ライブラリ

- **計測とレイアウトの量**
  - 折り返しの計算量が文字数の 2 乗になる。結果のキャッシュがない。
  - フォーカスを移すたびに、全部の層を配置し直す。
  - 確認ダイアログの表示中は、毎フレーム全体を配置し直す。
- **効果音のきっかけが粗い**
  - きっかけは 4 種類だけで、発生元の部品が分からない。
  - キャンセルできないダイアログでも、キャンセル音が鳴る。
  - 層を閉じるときに、アニメーションを挟む状態がない。
- **パッドとアナログ入力**
  - パッドのボタンを割り当てられない。
  - スティックの傾きを使えない。
  - フォーカスできる部品がない縦長の内容（クレジットなど）は、ホイールでしかスクロールできない。
- **アクセシビリティ**
  - フォーカスを色の違いだけで示している。
  - 部品の名前・値・種類を外から取り出す API がない（読み上げの手がかりがない）。
- **設定の反映**
  - 入れ替えのフックが `set()` のときしか動かない。そのため、元に戻す・読み込みの経路では検査されない。空のキーが入り得る。
  - 反映の方式は「即時」と「適用時」の 2 つだけ。「ドラッグを終えたら反映」がない。
- **ローカライズの残り**
  - 数値の書式（50% など）がコードに直接書いてある。
  - 複数形の表現がない。
  - 配置が「左・右」の絶対指定で、「行の始まり・終わり」ではない。
  - フォントの切り替え（その言語の文字がないときの代わり）がない。
  - 禁則処理がない。

### 3.2 描画基盤

- **文字の描画の効率と精度**
  - 文字幅を測るだけで、グリフの生成と GPU への転送が走る。
  - 最近使った順の管理の更新が、線形の探索になっている。
  - 同じ文字列を、毎フレーム 3 回走査する。
- **COM の初期化**：エンジン本体が COM を初期化していない。今は、どこかが暗黙に初期化しているから動いている（推測）。
- **スワップチェーン**
  - 構成が古い（バッファ 1 枚・DISCARD・MSAA）。
  - サイズ変更の経路が 2 本ある。
  - VSync を選べない。
- **DPI**：対応していない。表示倍率が 150% の環境では、全体がぼける（推測）。
- **文字描画の機能**
  - サロゲートペア（「𠮷」や絵文字）に対応していない。
  - カーニングがない。
  - 1024 文字を超えた分は黙って描かれない。
  - フォントは 1 種類だけ。
- **失敗時の扱いと例外**
  - 失敗したときの扱いが場所によって違う（例外・nullptr・黙って何もしない）。
  - 例外の型に共通の基底がない。
  - シェーダーのコンパイル結果をリークしている。
- **テクスチャの属性**：テクスチャ自身が「乗算済みアルファかどうか」を持っていない。そのため、描く側が毎回正しく指定する必要がある。

### 3.3 アプリへの組み込み

- **メインループ**
  - 待つ間も `Sleep(0)` で回り続け、CPU のコアを 1 つ使い切る。
  - 経過時間に上限がない。ウィンドウのドラッグ後に、時間が飛ぶ。
- **キーのメッセージ**
  - F2 や F5 を押し続けると、キーリピートで切り替えが連発する。
  - Alt や F10 を押すと、メニューモードに入る（推測）。
  - コマンドモードを抜けたときに、メニュー表示中でもカーソルが消える。
- **DPI とマルチモニター**
  - 解像度を変えると、ウィンドウがプライマリモニターへ飛ぶ。
  - DPI 対応を宣言していない。
- **ログ**
  - 出口が 4 系統ある。
  - 黙って無視される失敗が多い（未登録シーン・未知の設定キー・保存の失敗）。
- **設定変更の通知**
  - 全体で 1 つの連番を、各シーンが毎フレーム確かめる方式になっている。
  - FOV を反映しているのは GamePlayScene だけ。
- **リリースビルド**：リリースビルドでもデバッグ用のコンソールが開く。
- **使われていない状態・重複した状態**
  - フルスクリーンの状態を 3 か所が持っている。
  - `is_overlay()`・`is_paused()`・方向キーのスタックは、どこからも使われていない。
  - 方向キーのスタックには、未定義動作になる経路もある。

## 4. 根が同じ問題（まとめて直すと効くもの）

多くの指摘は、いくつかの根に行き着く。個別に直すより、根から直した方が手戻りが少ない。

| 根 | 関係する指摘 | 方針 |
|----|-------------|------|
| **入力が「フレームごとの bool」で、消費の仕組みがない** | B1, B2, B11, B27, C（パッド・キーリピート） | 入力を「イベントの列」にし、層ごとに消費する（ImGui → UI → ゲーム）。UI の中ではアクション ID で部品へ渡し、使わなければ親へ回す |
| **設定の「正しい値」が 1 つに定まっていない** | A1, A2, A3, B6, B24, B25, B26 | ストアだけを正とし、実行時の状態とは分ける。型付きのハンドルとメタデータを持たせる。ファイルは安全に書き、バージョンを持たせる |
| **遷移・寿命を文字列と即時実行で扱っている** | A4, A10, B7, B22, B23 | 遷移を型付きの要求にしてフレームの境目で実行する。ロードの状態を持たせる。終了は明示的に行う |
| **描画状態とリソースを暗黙の決まりと生ポインタで扱っている** | A5, A6, A9, B15〜B20 | 描画状態は明示的に指定する。2D の描画を 1 本の命令リストにまとめる。リソースは世代番号付きのハンドルで持つ |
| **GameMain がすべての中心にいて、テストから触れない** | B14, B28, C（ログ） | 依存を外から渡し、画面のロジックをシーンから切り離す |

## 5. 進め方の提案

1. **A を先に直す**。11 件で、どれも範囲が狭い。A1 は今回の UI 作業で入れた欠陥なので、最初に直す。
2. **B の中で、根（4 章）ごとにまとまりを選んで直す**。それぞれ設計とレビューを伴う規模になる。どの順番にするかは、次に何を作りたいかで決める。
   - **オプション画面や HUD を増やしたい**：入力のイベント化とアクション ID（B1・B2・B27）、レイアウトの 2 次元化（B3）
   - **見た目を作り込みたい**：2D の命令リストとバッチ化（B15〜B18）
   - **配布を考えたい**：設定ファイルの安全な保存と置き場所（B24〜B26）、DPI、デバイスロスト（A9）
3. **C は、関係する B を直すときに一緒に片付ける**。
